# FlyTest


[![CI](https://github.com/Teivrim/FlyTest/actions/workflows/ci.yml/badge.svg)](https://github.com/Teivrim/FlyTest/actions/workflows/ci.yml) [![license](https://img.shields.io/badge/license-MIT-5eead4.svg)](LICENSE) [![lines](https://img.shields.io/badge/lines-of%20code-lightgrey.svg)]()
Локальный цифровой цирк для виртуальной мухи. Rust-runtime с сенсорным
вводом и замкнутым контуром обучения, плюс `TFLY.h` — single-header
C-библиотека со всей моделью: сенсоры, боль, гормоны, эмоции, потребности,
память, обучение, сон, социальные сигналы.

```text
виртуальный мир → Observation → BrainModel → Action → Blender/мир → новое Observation
```

## Что внутри

| Слой | Язык | Что делает |
|---|---|---|
| `TFLY.h` | C, 106 КБ, single-header | ядро модели: биология мухи целиком |
| `native/tfly_ffi.c` | C | тонкий C ABI поверх ядра |
| `src/tfly.rs` | Rust | безопасные биндинги к C-ядру |
| `src/runtime.rs` | Rust | цикл наблюдение → действие → награда |
| `src/biology.rs` | Rust | гормоны, метаболизм, потребности |
| `src/flywire.rs` | Rust | импорт и анализ графа FlyWire FAFB v783 |
| `editor/` | JS + Three.js | визуализация состояния |
| `blender/` | — | бридж, запекает сцену и анимацию |

Зависимости Rust: `anyhow`, `clap`, `csv`, `flate2`, `serde`, `serde_json`,
`sha2`, `rusqlite`. Всё из crates.io, без вендорённого мусора.

## Два решения, которые стоит посмотреть

**`unsafe` запрещён на уровне крейта.**

```toml
[lints.rust]
unsafe_code = "deny"
```

Модуль `src/tfly.rs` ходит в C-ядру и вынужден использовать `unsafe` —
поэтому он локально делает `#[allow(unsafe_code)]`. Весь остальной крейт
continue считать `unsafe` ошибкой компиляции. Мост в C не должен
расползаться на пол-проекта: либо весь FFI в одном модуле, либо никак.

**`build.rs` не роняет сборку, если нет компилятора.**

Если C-компилятор недоступен, крейт всё равно собирается: биндинги к
`TFLY` компилируются out, и `crate::tfly` сообщает, что фичи нет.
Rust-часть проекта — то есть всё остальное — от C-ядра не зависит.
Кросс-компиляция и среды без тулчейна не ломают `cargo build`.

Переменная `TFLY_NO_BUILD=1` пропускает сборку C-ядра принудительно.

## Подключение своей модели

- `SyntheticFlyModel` и `ToyCircus` — автономный демо-цикл, работает
  без внешних зависимостей.
- JSONL-протокол для обмена с внешними моделями.
- Каталог адаптеров под PyTorch / ONNX / spiking / RL.
- Импорт графа связей FlyWire через SQLite; нормализация каналов
  `input` / `output` / `internal` / `endocrine`, нейромедиаторов и
  гормональных стандартов.
- Эвристика `signal → reaction → signal` по структурному графу.

## Использование ядра из своего кода

```c
#include "TFLY.h"

TFLY fly;
TNew(&fly);
TSeed(&fly, 7);

TLight(&fly, 0.6f);
TOdor(&fly, 0.4f);
TUpdate(&fly, 0.016f);
```

Зависимостей кроме `libc` и `libm` нет. Подключается одним `#include`.

## Сборка

```bash
cargo build --release
cargo run
```

Нужен C-компилятор для ядра; без него крейт собирается, но
`crate::tfly` сообщает, что C-фича недоступна (см. выше).

### Тулчейн: GNU, а не MSVC

Ядро использует `sincosf` — расширение glibc. В Windows CRT этого символа
нет, поэтому под MSVC линкер падает с `LNK2019: unresolved external symbol
sincosf`. Код написан под GNU-окружение (libc + libm) и собирается MinGW-w64;
CI в этом репозитории использует тот же тулчейн, чтобы проверять то, что
действительно работает.

Чтобы заработало под MSVC, в `TFLY.h` нужно заменить вызов на
`sinf`/`cosf` — это правка в одну строку в макросе, но она затрагивает
модель целиком, поэтому здесь не сделана.

Rust-часть проекта переносима: если C-компилятора нет, `build.rs`
компилирует биндинги out, и крейт собирается как чистый Rust. `unsafe` при
этом не появляется — `crate::tfly` просто сообщает, что фичи нет.

## Состояние

Экспериментальный проект. Модель мухи — упрощённая, на уровне сигналов и
реакций, а не биологически достоверная. Ценность в замкнутом контуре и в
инфраструктуре обмена с моделями, а не в точности биологии.

# FlyTest

FlyTest — локальный цифровой цирк для виртуальной мухи: Rust runtime с сенсорным вводом, управляющими действиями и гормональными импульсами, плюс слой анализа FlyWire FAFB v783.

Цель проекта — сделать замкнутый контур:

```text
виртуальный мир → Observation → BrainModel → Action → Blender/мир → новый Observation
```

## Подключение своей модели

- `SyntheticFlyModel` и `ToyCircus` — автономный демонстрационный цикл;
- JSONL-протокол для обмена с внешними моделями;
- Blender bridge, который создаёт простую сцену и запекает анимацию;
- каталог адаптеров для PyTorch/ONNX/spiking/RL-моделей;
- импорт и анализ FlyWire-графа через SQLite;
- нормализация каналов `input/output/internal/endocrine`;
- нормализация нейромедиаторов, нейропептидов и гормональных стандартов;
- эвристический `signal → reaction → signal` по структурному графу.

## TFLY.h: ядро модели

[`TFLY.h`](TFLY.h) — single-header C-библиотека со всей моделью мухи: сенсоры,
боль, гормоны, эмоции, потребности, память, обучение, сон, социальные сигналы.
Никаких зависимостей, кроме libc и libm. Подключается одним `#include`.

```c
#include "TFLY.h"

TFLY fly;
TNew(&fly);
TSeed(&fly, 7);

TLight(&fly, 0.6f);
TOdor(&fly, 0.5f, T_ODOR_FRUIT);
THeart(&fly, 0.8f, T_BODY_WING_L);   // боль в левом крыле
THormone(&fly, 0.4f, T_H_DOPAMINE, 2.0f);
TUpdate(&fly, 1.0f / 60.0f);

TPrintState(&fly);
```

Ключевые вызовы:

- `THeart(x, region)` — боль с локализацией по частям тела, рефлекс испуга и страх;
- `THormone(x, hormone, z)` — введение гормона, `z > 0` болюс, `z <= 0` тонический;
- `TAssociate(cue, action, outcome, modulator)` — трёхфакторное обучение;
- `TEmotion`/`TFear`/`TJoy` — прямое выставление аффекта для экспериментов.

Проверка и демо:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run_tfly.ps1
```

CLI через Rust-обвязку:

```bash
cargo run --release -- tfly --scenario learn
cargo run --release -- tfly --scenario pain --trace 2
cargo run --release -- tfly --scenario social
```

Архитектура, ответ на вопрос «давать ли модели только входы» и план развития —
в [`docs/tfly-design.md`](docs/tfly-design.md).

## FlyEditor

Запусти графический редактор:

```bash
cargo run --release -- editor --port 8765 --flies 3
```

Открой `http://127.0.0.1:8765`. В центре — арена с 2–3 мухами; слева — список агентов, справа — input/reaction/hormone/energy inspector и управление скоростью/decay. Runtime работает на fixed timestep 60 Hz, использует лёгкую политику и не пишет каждый кадр в SQLite/JSONL. Это режим, рассчитанный на 2–3 мух на текущем ПК.

FlyEditor не запускает полный FlyWire-граф в каждом тике: для него используется облегчённый realtime-адаптер. Полный граф подключается через `circus --model flywire` и Blender bridge.

### Полоса препятствий

Вместо прежних «приключений» с подвижной целью каждая сцена несёт **настоящий лабиринт**, а в его дальнем конце стоит еда. Персонаж идёт от входа к еде и получает награду, когда доходит.

Лабиринт строится в `src/course.rs` случайным обходом в глубину на сетке, поэтому путь через него ровно один: дойти — значит найти. Клетки, чьи центры выходят за пределы круга сцены, в лабиринт не входят, так что граница сама собой принимает форму сцены. Вход и еда — концы самого длинного пути, а не западный и восточный край: полоса «край к краю» выходила такой же скучной, как её seed, и её можно было пройти по прямой.

Каждый раунд лабиринт строится заново, поэтому маршрут, изученный в прошлом раунде, ничего не стоит. Раунд длится 62 с — число снято с замеров, а не взято на глаз; обычно успевает добраться первая, а остальные идут по её следу.

#### Что персонажу известно, а что нет

Ему отдаётся **граф проходов** и названия клеток. Это стоит назвать прямо, а не объявлять картой: маршрут ему не отдаётся, расстояние до еды не отдаётся, в какую сторону еда — не отдаётся. Неправильную ветку он пробует первой, из тупика выбирается сам, каждый метр проходит ногами, и ничего из этого не переносится в следующий раунд. Не сообщается только арифметика того, какие клетки соединены, — без неё он раунд простаивал бы в дверном проёме, выясняя это.

#### Поиск

`Search` в `src/editor.rs` держит дорогу, пройденную ею, множество посещённых клеток и множество клеток, где все выходы оказались тупиками. Пока есть куда идти вперёд — идёт; закончилась ветка — идёт назад по дороге, и разговор продолжается оттуда, куда пришла. На вырезанном лабиринте, который является деревом, это доходит до еды всегда.

Отступ — это место, куда надо **дойти**, а не место, куда записали, что она пришла: поправка заносила её на три клетки вперёд, и поиск просил её пройти сквозь стену.

Решение держится, пока ноги не в середине той клетки, куда собрались. Граница между клетками проходит ровно посреди проёма между ними, так что в проёме её называют то одной клеткой, то другой; персонаж, передумывающий каждый тик, разворачивается в пороге и не проходит.

#### Стены и столкновения

Стена — это плита, а столкновения — круги вдоль неё, выведенные из тех же отрезков, которые рисует клиент (`Course::solids`). Поэтому стена, которую видно, и стена, об которую не пройти, — один и тот же объект.

Круги вдоль стены идут **внахлёст**, а не впритык: между кругами, расставленными через диаметр, остаётся щель, в которую помещается точка, но не помещается персонаж. Щель — это дыра: «проход свободен» проверяется точкой, точка в щель пролезает, и персонаж упирается в стену, которую уже прошёл.

Выталкивания **складываются** и применяются одним ходом, а входящая в стену составляющая скорости гасится. По очереди стены не развести: вытолкнуло из одной — вдавило в соседнюю, и персонаж застревал в углу; сходящиеся выталкивания уводят по диагонали, то есть наружу. Гасить скорость нужно потому, что рулёжка пересчитывается каждый тик и заново приносит весь толчок, которым её впечатали в стену, — без этого она жмётся в стену на полной скорости, вместо того чтобы скользить по ней.

#### Остальное, что видно

Тот, кто доел, оставляет след, и остальные по нему идут — единственное, чему персонаж учит другого. След рисуется цветом персонажа, так что первый прошедший виден как тот, за кем идут.

Последняя дошедшая **не закрывает раунд в тот же тик**: раунд стоит ещё `FEED_PAUSE` секунд, еда исчезает, счёт виден. Иначе лабиринт перестраивается под ними, и все снова оказываются у входа прежде, чем отрисовался хоть кадр: результат никто не видит, и панель не успевает сказать, кто выиграл.

### Походка

Каждая муха имеет собственный адаптивный policy-вектор:

- `reward` — EMA полученной награды, растёт при выполнении цели и по кнопке `Награда`;
- `novelty` — EMA исследовательской новизны, растёт при низкой награде;
- `strategy` — переключается между `balanced`, `exploit_reward` и `explore_novelty` по порогам `reward > 0.6` и `novelty > 0.68`.

Кнопка `Награда` штрафует/поощряет выбранную муху вручную, `Puff` вызывает событие. Счётчики событий: `metrics.total_puff_events`, `metrics.learning_updates`.

Это адаптивная эвристика поведения, а не обучение нейросети: веса обновляются онлайн по сигналу награды, без backpropagation.

### «Puff»

Триггерное событие: муха периодически (раз в ~6 с sim-времени, со своим фазовым сдвигом) выпускает зелёное облако, которое рассеивается ~2 с и слегка повышает её `stress`. В 3D это три полупрозрачных сферы, растущих и растворяющихся за корпусом. Кнопка `Puff` вызывает событие вручную.

Это стилизованная механика цирка, не биологическая модель выделения газов у насекомых.



## Blender-сцена

Установи Blender 3.6+ и выполни:

## Научное ограничение

FlyWire даёт структурный коннектом и coarse-аннотации, но не содержит временных рядов мембранного потенциала, концентраций гормонов, состояния рецепторов и поведенческих измерений. Поэтому встроенная модель — воспроизводимый структурный прототип, а не перенос субъективного сознания или количественная биологическая симуляция.

Подробности: [`docs/signal-model.md`](docs/signal-model.md).

## Цифровой цирк в FlyEditor

Вокруг центральной арены стоят пять сценических площадок. Каждая учит муху
одному уроку, и урок закрепляется настоящим трёхфакторным обучением из
`TFLY.h`, а не анимацией.

| № | Акт | Сигнал | Что выучивает |
|---|---|---|---|
| 1 | Главная арена | яркий свет | свет вызывает танец |
| 2 | Лабиринт | вибрация пола | вибрация ведёт к цели |
| 3 | Чародейный сад | запах фрукта | запах ведёт к еде |
| 4 | Фабрика чудес | стук | стук требует точного движения |
| 5 | Пустота | темнота | в темноте нужно замереть |

Нажатие на номер акта отправляет туда всю труппу, а галочка «только
выбранная» — одну муху. Клавиши `1`–`5` делают то же самое и заодно
подводят камеру к площадке.

### Цифровой цирк

| Походка | Характер |
|---|---|
| `W` `A` `S` `D` | ходить по арене относительно камеры |
| `Q` / `E` | опустить / поднять точку обзора |
| `Shift` | ускоренное передвижение |
| `1`–`5` | перейти к акту и отправить туда мух |
| `C` | вернуть камеру в центр |
| мышь | облёт, колесо — приближение |

Камера вращается вокруг подвижной точки обзора, а не вокруг начала координат,
поэтому до каждой площадки можно дойти пешком и рассмотреть её вблизи.
Точка обзора ограничена куполом (−9…9 по горизонтали, 0.2…5.5 по высоте),
иначе сцена уходит в туман.

### Походка

Панель «ОБУЧЕНИЕ» показывает состояние мозга выбранной мухи: мастерство,
вес ассоциации, гейт обучения, пластичность, число проб, XP и уровень.
Строка «мысль» — это отображение реального состояния мозга, а не заготовка.

- `Тренировать 200` — прогнать 200 проб выбранной мухи;
- `Авто` — непрерывные пробы с заданной частотой;
- `ε` — вероятность случайного действия вместо лучшего выученного;
- `Боль` — сигнал боли, который должен перебить выученный план;
- `Допамин` — открыть гейт обучения;
- `Забыть` — стереть ассоциации, оставив тело.

Мастерство читается прямо из веса связи в C-ядре, поэтому невыученный урок
так и остаётся невыученным.

## Проверки

### Целостность текста

Русский в интерфейсе — это данные, а не украшение, и одна ошибка кодировки
делает его бесполезным. Проверка живёт отдельно от сборки:

```
python scripts/check_russian.py
```

Она ищет три вещи, которых в живом русском тексте не бывает: символ
замены `U+FFFD`, латиницу из Latin-1 (не считая `«» — – … × · ° №`) и
кириллицу, которой нет в русском алфавите. Последнее — главное: строка,
прочитанная не в той кодировке, состоит почти целиком из таких букв.

Что портит текст по-настоящему — `Set-Content` в PowerShell 5.1 без
`-Encoding UTF8`: он пишет в ANSI, и кириллица рассыпается. Строка в
тринадцать символов после нескольких таких проходов становится на десятки
тысяч, и восстановить её арифметически нельзя. Файлы читает и пишет
`edit`/`write`, они держат UTF-8.

Есть и вторая, тихая ошибка: строка может быть *прочитана* правильно, но
оказаться не в той таблице. Проверка этого — в тестах, и они спрашивают
C-ядро, а не сравнивают два списка между собой:

- `emotion_keys_are_the_core_keys_in_the_core_order` — сверяет ключи
  эмоций с тем, что ядро возвращает по индексу. Список, сдвинутый на
  один, даёт «радость» с ключом `sadness»;
- `a_name_from_one_table_never_appears_in_another` — «петляющий» это
  походка, и в таблице жестов или встреч означает ошибку;
- `emotion_names_are_distinct_and_all_present`,
  `act_labels_are_distinct` — одинаковые подписи в таблице, которую
  читает человек, невозможно не заметить, но легко пропустить;
- `training_and_gait_report_what_they_actually_did` — строки лога обязаны
  называть номер уровня и реальную походку;
- `gate_terms_sum_to_the_gate` — список слагаемых гейта обязан
  складываться в сам гейт, и проверка покрывает оба края среза;
- `the_gate_still_teaches_nothing_when_shut_at_any_rate` — закрытый
  модулятор не учит ни при какой скорости;
- `a_faster_rate_reaches_the_same_lesson_sooner`,
  `the_learn_rate_reaches_every_fly_including_new_ones`;
- `the_panel_states_the_association_it_is_training`,
  `the_panel_reads_russian_rather_than_core_keys`;
- `the_last_outcome_says_what_the_trial_was`.

### На чём персонаж учится

Панель «ОБУЧЕНИЕ» отвечает на этот вопрос прямо: крупным шрифтом
сама ассоциация — `яркий свет → танцевать` — а под ней четыре числа.

**Вес связи** — это и есть «выучено». Показан крупно, потому что это
единственная величина, которая отвечает на вопрос.

**Верность** — доля верных ответов, и она лежит рядом с весом, потому
что раньше эти два числа стояли рядом без пояснений и читались как
«мастерство 90%, вес 1%», то есть как противоречие. Противоречия в
нём нет: политика, читающая плоскую матрицу, продолжает угадывать
верно по счастливому совпадению. Соблазн растёт ещё и оттого, что при
полностью выученном уроке верность *падает* — шум разведки никуда не
делся. Поэтому вес и верность подписаны раздельно, а у верности есть
приписка «угадывает, а не помнит».

**Гейт** — третий фактор правила трёх факторов, и в пробе он
единственный, который можно потерять: остальные два встроены в пробу.
Открыт он раскладкой `из чего сложен гейт`: базовый уровень, дофамин,
октопамин, нейропептид F, серотонин, темнота, с вкладом каждого.
Серотонин — единственный, кто тянет вниз. Числа не выдуманы: это те же
коэффициенты, что в `TLearningGate`, и `gate_terms_sum_to_the_gate`
сложит слагаемые и сравнит с тем, что вернуло ядро. Срез в 0..1 тоже
показан отдельным слагаемым, иначе в разгар обучения список даёт 123%
против заявленных 100% и перестаёт объяснять то, что объясняет.

**Пластичность** — сколько обучения доступно в принципе.

Под числами — `осталось проб`, посчитанное из *измеренной* скорости
роста веса, а не из констант ядра: константы не вся правда, след
готовности и модулятор двигают настоящую скорость тоже. Если вес не
движется, там написано «вес не движется» вместо числа проб.

Под всем этим — мысль персонажа. Она уже была и тоже отвечает на
вопрос, но отвечала словами вроде «верно», которые ничего не сообщали о
том, что именно проверялось.

### Темп обучения

Ползунок `Темп обучения` умножает размер разрешённого изменения веса,
`TAssociate` берёт `0.02 · plasticity · learn_rate`. Это скорость
обучения, а не четвёртый фактор правила: при закрытом гейте не учит
ни ×1, ни ×20, и это проверяется отдельно — в C-тестах и в Rust.

Собственное значение ядра — честное и медленное. При широко открытом
модуляторе урок берётся за ~100 проб, при бедном — за тысячи, потому
что гейт множит всё обучение, а он ходит вместе с гормонами. Разница
видна прямо:

| темп | 20 | 40 | 60 | 80 | 100 | 120 проб |
|---|---|---|---|---|---|---|
| ×1 | 0% | 1.7% | 4.5% | 8.3% | 11.5% | 15.1% |
| ×4 | 8.9% | 23.1% | 37.7% | 55.5% | 71.5% | 86.2% |
| ×12 | 23.8% | 59.9% | 96.0% | 100% | 100% | 100% |

### Модель

Мухи больше не летают. Они ходят по арене, и у каждой — стилизованная
аниме-фигурка: хиби-пропорции, платье, крупные глаза с бликом, румянец, две
косички. От насекомого остались только усики и сложенные за спиной
полупрозрачные крылья — напоминание, что летать они больше не умеют.

### Обучение

Персонаж не «анимируется», а отображает состояние C-ядра. Ходьба приходит не
одним числом, а траекторией суставов: `TGaitLimbs` отдаёт четыре сустава
риг всегда читает объединение.

| Клавиши | Действие |
|---|---|
| ноги | бедро, колено, щиколотка, разворот стопы |
| руки | плечо, локоть, запястье, разворот |

| Параметр походки | Что делает |
|---|---|
| `stride` | длина шага, амплитуда бедра и высота подъёма стопы |
| `cadence` | темп, частота шагов |
| `sway` | качание; чем больше, тем ниже устойчивость и шире разворот стоп |
| `balance` | равновесие: 1 — стоит ровно, 0 — падает |

Траектория ноги устроена как настоящая: нога почти прямая на опоре, колено
сгибается один раз в середине опоры, а при махе складывается сильно, чтобы
стопа прошла над землёй. Колено, гнущееся при опоре, — это хромота; колено,
который держит обиду минуту, — это разные существа.

Ноги противоположны по фазе, и **каждая рука противоположна своей же ноге** —
без этого кукла выглядит именно куклой. Руки живут своей жизнью: теряя
равновесие, персонаж начинает ими разводить в темпе, не совпадающем с шагом,
потому что баланс и есть работа рук как отдельного привода. Размах рук
ограничен диапазоном, который плечо в состоянии: ветерок с перелётом читается
как паника, а переразогнутое плечо — как сломанная сетка.

### Стоять на полу

Персонаж стоит на полу ровно настолько, насколько позволяют применённые углы.
Фиксированная высота не работает: стопа поднимается на махе и опускается на
опоре, и при постоянной высоте персонаж то тонет по щиколотку на
переставном шаге, то висит на задней ноге.

Высота считается прямой кинематикой вниз по цепи, и в этом деле три вещи
неочевидны, каждая стоила проваливания:

- **Подошва — не точка под щиколоткой, а эллипсоид.** Нога длинная: при наклоне
  щиколотки дальний конец туфли уходит вниз намного дальше точки. Точка
  завышает высоту стопы почти на треть ноги, и персонаж висит на согнутом
  колене.
- **Туфля смещена вперёд от сустава**, и наклон увеличивает её свисание. Без
  этого слагаемого просто наклонённая нога уходит под пол.
- **Угол щиколотки накопленный, а сустав локальный.** Модель отдаёт полный угол,
  потому что по нему считается пол. Риг применяет его как локальный — и
  получает наклон дважды, бедром и коленом сверху, и ходит с носком в земле.

Пропорции заданы один раз в `RIG` и используются и для геометрии, и для
расчёта пола, и для отправки в модель, поэтому разъехаться они не могут. Две
реализации одного расчёта — в C и в JS — сверяются тестом, иначе они
тренируются раздельно.

Замеренный результат: было 0.195 проваливания (пятая часть роста), стало 0.000
с остатком 0.5–2.4 мм — это тесселяция сферы-туфли, а не логика.

Приседание от потери равновесия выражается сгибанием коленей, а не опусканием
корня: человек приседает, сгибая ноги, и не проваливается сквозь пол.
Вертикального «боба» на корень тоже нет — он уже есть в траектории ног, и
второй раз его посчитать значит оторвать стопы от земли на каждом шаге.

### Ступени и стены

Сцена — приподнятый диск, и персонаж на ней **стоит сверху**. Раньше она
отдавала высоту, которой нет, и всякий, кто выходил на сцену, оказывался по
щиколотку внутри неё. Высота под ногами теперь часть снимка, сглаживается, и
край сцены получается ступенькой, а не скачком: вверх быстрее, чем вниз.

Сквозь стены лабиринта, стебли сада и посты ходить нельзя, и геометрия сцены
строится в 3D **из тех же чисел**, по которым разрешаются столкновения. Два
набора координат — это два шанса поставить стену в одном месте, а её
коллайдер в другом, и баг невидим, пока кто-нибудь не пройдёт сквозь стену.

Столкновение живёт в теле, а не отдельным проходом после движения. Проход,
идущий **после** перемещения, бесполезен: руление пересчитывает скорость с
нуля каждый тик и выбрасывает всё, что снаружи записали, — персонаж идёт в
стену на полной скорости, и её потом оттуда выталкивают. Тело получает от мира
список твёрдого и разруливает сам, сразу после сдвига.

Персонаж не упирается в стену, а скользит по ней: сначала сцена притягивает к
центру, потом стена отталкивает, и равновесие наступает ровно там, где
столкновение выталкивает. Сцена должна быть достаточно широкой, чтобы это
работало, иначе стена продавливается внутрь, а не отталкивает наружу.

**Орбита, по которой персонаж кружит, не должна выходить в чистый центр
сцены.** Лабиринт это нарушал: пять широких стен оставляли чистый центр 0.39
при радиусе сцены 1.7 — это не пол, а стена стен, и персонаж в нём намертво
прижимался. Теперь простор считается **из самих коллайдеров**, а не пишется
рядом отдельным числом, и орбита ограничивается тем, что сцена реально может
предложить. Проверяется тестом на каждом акте.

### Ноги не едут

Фаза ходьбы следует за землёй, а не за своими часами. Раньше она шла с
темпом, выбранным по каденции, и к скорости тела отношения не имела: ноги
циклили втрое быстрее, чем земля двигалась, и стопы ехали назад.

Мир сообщает модели, насколько далеко она прошла, и модель владеет правилом, что
шаг покрывает длину шага, поэтому измерение и правило остаются на своих
местах. Скорость меряется по смещению, а не берётся из поля скоростей: руление
охотно сообщает о скорости, которой тело не достигает. Быстрый каденс при той
же скорости делает шаги короче, а не цикл чаще, — так выученный stride меняет
саму походку, а не только скорость качания ног.

Стоя на месте, персонаж не марширует, а садится в стойку на опорной ноге.

Есть четыре походки, и персонаж **учится выбирать** между ними:

| Клавиши | Действие |
|---|---|
| торопливый | короткий быстрый шаг |
| Клавиши | Действие |
| петляющий | сильно шатает, минимальная устойчивость |
| длинный | длинный шаг, часто спотыкается |

Каждая проба ходьбы — это заход: персонаж примеряет походку, идёт 40 кадров и
получает оценку `2·дистанция − 1.5·энергия − 0.6·споткнулся`. Оценка
записывается **тем же трёхфакторным правилом**, что и уроки актов, поэтому
персонаж с закрытым гейтом не учится ходить вообще.

Важная деталь: проба меряет **пройденную дистанцию, а не продвижение к сцене**.
Персонаж уже стоит на своей сцене, поэтому «продвижение» всегда около нуля и
не несёт сигнала. Умение ходить и умение найти дорогу — разные уроки, и они
до тошноты.

Обучение ходьбой идёт параллельно с обучением урокам: каждая проба урока
сопровождается пробой походки. Кнопка `Учить ходить ×200` прогоняет их
пачками, `Сменить походку` перебирает варианты вручную.

### Обучение

26 эмоций вместо 14, и все они **выводятся из состояния**, а не висят мёртвым
грузом:

- `облегчение` — падающий край боли, а не её отсутствие;
- `скука` — нарастает, когда ничего не происходит;
- `надежда` и `разочарование` — из неудовлетворённых потребностей;
- `привязанность`, `доверие`, `тоска`, `ревность`, `застенчивость` — из
  социальных сигналов; затухают медленно, потому что о близком помнят долго;
- `благодарность`, `сочувствие` — производные от облегчения и грусти.

У каждой эмоции своё время жизни: боль 2 с, удивление 1.5 с, скука 14 с,
доверие 30 с. Персонаж, который забывает удар за полсекунды, и персонаж,
который держит обиду минуту, — это разные существа.

Надежда и скука влияют на походку: с надеждой шаг быстрее и ровнее, со скукой
медленнее. Эмоции тонируют платье — радость греет, страх холодит.

### Обучение

Лицо — не декорация поверх модели, а ещё один набор выходов того же C-ядра.
Риг читает десять каналов и ничего не решает сам.

| Приключение | Что происходит |
|---|---|
| `blink` | веки: 0 — открыты, 1 — закрыты |
| `gaze_x`, `gaze_y` | взгляд: куда и вверх/вниз |
| `pupil` | зрачок: 0.5 сужен, 1.6 расширен |
| `brow` | брови: −1 хмуриться, +1 поднять |
| `mouth` | рот: −1 грустная дуга, +1 улыбка |
| `mouth_open` | раскрытие рта |
| `blush` | румянец |
| `tears` | слёзы |
| `sweat` | пот |

**Моргание не таймер.** Частота растёт от усталости и падает от испуга, поэтому
уставший персонаж моргает медленно и часто, а испуганный почти не моргает. Сон
закрывает глаза сам; удивление подавляет моргание; боль принудительно смыкает
подругу.

**Слёзы — резервуар, а не зеркало грусти.** Грусть приходит и уходит быстро,
слёзы отстают от неё и высыхают медленно, поэтому персонаж может плакать, уже
перестав грустить. Потолок 0.85: лицо, льющее слёзы на максимуме при улыбке,
читается как сбой отрисовки, а не как печаль.

**Взгляд выбирается, а не сканируется равномерно.** Персонаж смотрит на того,
кто его держит в поле внимания: на партнёра, на соперницу, на угрозу. Если
внимания нет — глаза медленно плывут в стороны. Закрывающееся веко тянет взгляд
вниз. Назвать цель — значит обратить на неё внимание, поэтому взгляд
захватывается сам, а `look_strength` регулирует, насколько прочно. Тревога
любого рода снимает захват: испуганная персонажка не будет уставиться на
веки.

### Цифровой цирк

У веки два канала, и они отвечают на разные вопросы. `blink` — рефлекс: он не
даёт глазу пересохнуть. `eye_open` — решение, и именно оно позволяет открыть
глаза намеренно. Веко закрыто, если закрыть хочет хотя бы один из них, поэтому
риг всегда читает объединение.

**Пробуждение — последовательность, а не выключатель.** Первые полторы секунды
она вытирает сон несколькими медленными неполными морганиями и только потом
смотрит по-настоящему. Без этого открытие глаз читается как щелчок тумблера.

**Испуг будит, а не просто поднимает веки.** Рефлекс, который лишь открыл бы
глаза спящей, оказался бы хуже бесполезного: глаза распахнулись бы и снова
закрылись, потому что на самом деле никто не проснулся. Порог возбуждения
должен доходить до состояния сна — без этого «осознанному» открытию нечего
осознавать. Зафиксировано вживую: `blink 0.264 → 0.006` за 0.43 с, бровь вверх,
и персонажка остаётся на ногах.

Прищур — отдельная форма, а не моргание: сужает глаз, не закрывая его. Свет
адаптируется, и на пробуждении глаза ещё прищурены. Голова опускается вместе с
веками и поднимается вместе с ними.

### Обучение

Лицо не говорит, собрана персонаж или расслаблена, поэтому осанка — отдельная
группа выходов: `spine` (сгорбиться ↔ распрямиться), `shoulder` (плечи вверх),
`lean` (наклон вперёд ↔ назад).

Страх сворачивает её в кокон и поднимает плечи, гордость расправляет, печаль
опускает плечи, а сон горбит независимо от настроения. Это слой, который
читается через весь шатёр, где лицо слишком мелко.

### Цифровой цирк

Персонаж делает четыре вещи сразу: идёт, держит себя как-то, жестикулирует и
живёт лицом. Каждый слой только **прибавляет** к общему накопителю, и в риг он
когда голова двигается.

Прямая запись в сустав выглядит рабочей, пока два слоя не коснутся одного
сустава: второй молча стирает первый. Так персонаж замирала посреди шага
каждый раз, когда жестикулировала. Теперь она может идти и махать одновременно:
сложение, а не замена. Проверено: поклон даёт `spine 0.55`, страх ещё `0.16`,
вместе `0.742` — оба слоя на месте.

Привязано больше суставов, чем было: торс сгибается отдельно от головы, шея
поворачивается отдельно от торса, руки висят на плечевых суставах и могут
подняться выше головы, бёдра качаются, а волосы на пружине отстают от поворота
головы с лёгким перелётом. Без этого волосы выглядят приклеенными в тот момент,
пишется один раз.

Слой выражения живёт в теле, а не только в лице: улыбка, которая не доходит до
плеч, читается как маска; вопрос заставляет склонить голову, причём
несимметрично, как настоящий; стыд сжимает и отводит взгляд.

### Обучение

Два персонажа встречаются, когда стоят рядом, оба не на кулдауне и хотя бы один
хочет компании. Вид встречи выбирается по настроению пары, поэтому два
испуганных персонажа утешают друг друга, а доверчивые делятся.

| Клавиши | Действие |
|---|---|
| поздоровались | радость, доверие, связь +0.08 |
| поклонились | доверие, связь +0.06 |
| похлопали ладони | сильная радость, связь +0.10 |
| утешили | доверие, связь +0.14 |
| поделились | сильная радость, доверие, связь +0.18 |
| поссорились | злость, страх, связь −0.12 |
| разошлись | ничего, связь −0.01 |

Встреча **симметрична**: оба чувствуют одно и то же и оба двигают связь в одну
сторону. Встреча, которая двигала только одну сторону, не была бы отношениями.
При этом у пары есть лёгкая асимметрия, чтобы два героя не зеркалили друг друга
тренируются раздельно.

Связь растёт теплее у ласковых персонажей: холодному приветствие значит меньше,
чем привязчивому. Кульминация сдержана: испуг — жёсткий тормоз, потому что
раненый зверь прячется, а не знакомится. Без этого слагаемого искалеченная
персонажка всё ещё шла бы навстречу тому, кто её покалечил.

Есть восемь поз, которые риг умеет показать: покой, приветствие, поклон,
хлопки, указание, утешение, плечики, «прошу обнять». Поза идёт по конверту
с мягким началом и концом, поэтому её видно как движение, а не как мгновенную
смену позы. Автоматическая встреча не прерывает позу на полпути; кнопка
`Жест` — прерывает, потому что молча проигнорированное нажатие выглядит как
тренируются раздельно.

**Личное пространство.** Два персонажа не стоят внутри друг друга: мягкое
отталкивание по линии между ними, и радиус берётся из состояния, а не задан
константой. Страх и стыд расширяют круг, связь сужает — знакомый человек
тот, рядом с кем стоишь ближе.

**Взгляд на партнёра.** После встречи персонаж смотрит на того, с кем только что
говорил, и партнёр смотрит в ответ. Канал взгляда намеренно отделён от
моторного аттрактора: притяжение говорит, куда идти, и спорит с тем, что не
согласовано; взгляд говорит, куда смотреть, и должен уметь перебить притяжение,
не помешав ей идти. Персонаж охотно пойдёт куда-то, пока смотрит на другую.

### Обучение

Помимо уже перечисленных, для работы с телом и лицом:

| Приключение | Что происходит |
|---|---|
| `sleep` с `value: 1` / `0` | усыпить / разбудить |
| `startle` | испуг: глаза распахиваются, спящая просыпается |
| `gesture` с `value: 0..7` | задать позу вручную |
| `meet` | познакомить двух персонажей |

Кнопки `Усыпить` и `Испуг` в панели ОБЩЕНИЕ делают то же самое. Без них
последовательность пробуждения была бы видна только через JSON: ждать, пока
энергия кончится, — минуты модельного времени.

## Персонажи

`agents[]` в снимке — по одному на персонажа, 34 поля. Что из них важно
понимать, а что просто зеркало состояния:

**Где она.** `position` и `velocity` в мировых координатах, `ground` — высота
земли под ней. Персонаж мировых координат не знает: всё, чем она
пользуется, это сенсоры `light`, `odor`, `touch`, `temperature` плюс память о
тупиках.

**Что в ней происходит.** `drive` (текущая потребность), `decision`,
`attention`, `confidence` — строки, читаемые человеком. `energy`, `stress`,
`neurotransmitter`, `reward`, `novelty`, `hormone_level` — числа. Смысл
модели в том, что строка выводима из чисел, а не наоборот.

**Как она выглядит.** `gait` (походка), `face` (мимика), `posture`, `limbs`,
`social` (поза и жест), `affect` — список эмоций с силой. Это то, что
рисуется на сцене, и то, что меняется при обучении: походка и мимика
перестраиваются вместе с памятью, а не по отдельному таймеру.

**Что она съела.** Живёт не в персонаже, а в `runners[]` внутри
`courses[]`: `fed` (дошла до еды в этом раунде), `ate_feed` (самая глубокая
еда, до которой дошла, считая от входа), `ate_count` (сколько всего),
`feeds_total` (сколько есть), `distance` и `progress`. Панель показывает
«съедена еда: N из M», и это и есть оценка раунда. `ate_feed` важнее
`fed`: `fed` говорит, что она дошла хоть до чего-то, `ate_feed` — насколько
глубоко, а в лабиринте из сотни комнат это разные вещи.

**Обучение.** `training` — общие настройки: `enabled`, `epsilon`,
`learnrate`, `log_path`, `current_act`. Персонажная часть — `strategy`,
`hormone_enabled`, `puff_enabled`, `puff_level`, `puff_count`: что модель
считает стратегией, включены ли гормоны и надувается ли она.

## Проверки

Всё запускается одной командой:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/check_all.ps1
```

Семь проверок, в порядке от дешёвой к дорогой:

| проверка | что ломает |
|---|---|
| `cargo fmt --check` | форматирование |
| `cargo clippy --all-targets -- -D warnings` | предупреждения линтера |
| `cargo test --release` | 83 теста рантайма и генератора |
| C-ядро `native/tfly_test.c` | `TFLY.h`, который cargo не собирает |
| `node --check editor/app.js` | клиент: он вне сборки cargo, и опечатка в нём жила до того, как кто-то откроет страницу |
| `scripts/check_russian.py` | русский текст интерфейса |
| лимит памяти | редактор стартует, его RSS снимается 20 раз и обязан остаться под 100 МБ |

Последняя проверка существует потому, что сто мегабайт — требование, а не
пожелание, а требование, которое никто не меряет, тихо перестаёт выполняться.
Сейчас редактор стоит на 5 МБ, то есть запас двадцатикратный; проверка нужна
не ради текущего числа, а чтобы никто не уронил его незаметно.

Код возврата ненулевой, если упала хотя бы одна, поэтому скрипт годится и в
CI: job `gate` в `.github/workflows/ci.yml` вызывает его на каждом пуше, целиком,
включая проверку памяти.

`-SkipMemory` убирает последнюю проверку — нужно там, где нельзя занять порт.

Комментарии в самом скрипте английские намеренно: Windows PowerShell 5.1
читает файл в OEM-кодировке, если в нём нет BOM, и русское тире в комментарии
превращается в ошибку разбора. Пользовательский текст проекта русский, код
вокруг него — нет.

По частям, если нужно быстро:

```bash
cargo fmt --all -- --check
cargo check
cargo test
cargo clippy --all-targets --all-features -- -D warnings
python -m py_compile blender/flytest_bridge.py models/example_policy.py
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run_tfly.ps1
```

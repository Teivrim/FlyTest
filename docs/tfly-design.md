# TFLY: архитектура и обучение

Документ отвечает на два вопроса:

1. как выстроить входы, эмоции и обучение, чтобы модель была «умной»;
2. что именно реализовано в [`TFLY.h`](../TFLY.h) и почему так.

---

## 1. Главный вопрос: давать ли модели только входы?

Короткий ответ: **нет, но и эмоции не должны быть кнопкой.**

Есть три возможных архитектуры, и у каждой есть конкретная болезнь.

### Вариант A: только входы → выход

```text
сенсоры → [модель] → моторы
```

Модель становится рефлексной машиной. Она не может:

- предпочитать одно другому без явного сигнала за это;
- испытывать то, чего ещё не было в сенсорах;
- вести себя непредсказуемо для наблюдателя, то есть выглядеть «живой».

Это классический рефлекс Тромперера, и он бесполезен для цифрового цирка.

### Вариант B: эмоции как вход

```text
[эмоции снаружи] + [сенсоры] → [модель] → моторы
```

Теперь внешний оператор может «нажать» страх и посмотреть на реакцию. Полезно для
экспериментов, но если так делать всегда, получается **марионетка**: муха не
причиняет себе эмоций, их вызывают снаружи. Никакой автономии.

### Вариант C: эмоции — внутреннее состояние, внешний вызов — инструмент

```text
                        ┌──────────┐
  сенсоры ──────────────▶│          │──▶ моторы
                        │  нервная  │◀── действия меняют мир
  потребности (drive) ──▶│  система  │
                        │          │
  химия ────────────────▶│          │──▶ поведение
                        └──────────┘
                             ▲
   THeart / THormone / TFear ──┘   (внешнее вмешательство, не источник)
```

Это то, что реализовано. Ключевые решения:

| Решение | Следствие |
|---|---|
| Потребности (drive) растут сами, их нельзя «сделать» извне без затрат | У мухи есть собственные мотивы |
| Эмоции — переменные состояния с затуханием | Страх проходит, если причину убрали |
| `TFear(f, 0.8)` существует, но это **инструмент эксперимента** | Можно изучить, что будет, если страх «извне» |
| Страх подавляет еду и ухаживание даже при высоком секс-драйве | Потребности конфликтуют, как в жизни |
| Новизна сама порождает любопытство | Муха исследует без внешнего пинка |

**Практический вывод.** Твои `THeart` и `THarmone` — правильная идея, но
использовать их надо как *экспериментальный инструмент*: дать боль, посмотреть
реакцию, вылечить, посмотреть восстановление. Если вызывать их каждый кадр, ты
получишь цаплю, а не модель.

## 2. Почему нельзя просто «дать всё»

Главная ловушка при создании «живой» модели — **обучать на том, что ты сам
подал**. Если ты вызываешь `THeart` и потом учишь муху избегать источника боли,
она выучит «избегать всего, что ты назвал болью». Если ты вызываешь `THarmone`
перед каждой наградой, гейт обучения будет всегда открыт, и муха станет
рефлексной машиной с бесконечной пластичностью.

Правило: **внешние вызовы — для разведки и калибровки. Обучение должно
опираться на то, что муха обнаружила сама.**

## 3. Как выстраивать обучение

### 3.1 Трёхфакторное правило (уже реализовано)

Это самый важный элемент. `TAssociate` в `TFLY.h`:

```c
delta = lr * elig[action] * outcome * modulator
```

| Фактор | Что это | Пример |
|---|---|---|
| 1 | След активности (eligibility trace) | Муха летела вперёд |
| 2 | Исход (outcome) | Получила сахар |
| 3 | Модулятор (dopamine, octopamine) | Нейрохимия |

Ключевое свойство: **убрать модулятор — и обучение прекращается.** Это не
трогательная метафора, это реальный механизм: у мух обучение при низком
дофамине не работает. В модели это проверяется тестом
`editor`/`learning_requires_a_modulator`.

### 3.2 Гейт зависит от состояния

```c
gate = 0.15
     + 0.55 * dopamine      // «это было хорошо»
     + 0.45 * octopamine    // «это было важно»
     + 0.25 * npf
     - 0.35 * serotonin     // сытость закрывает обучение
     + 0.20 * darkness;     // ночная муха учится лучше
```

Одна и та же ситуация в разном состоянии — это разный опыт. Именно это даёт
ощущение характера, а не рефлекторной дуги.

### 3.3 Разделение эмоций по времени жизни

```c
pain        2 s    боль — быстро и коротко
surprise    1.5 s
curiosity   3 s
anger       3 s
fear        5 s
joy         6 s
dread      10 s
contentment 10 s
```

Муха, которая забывает удар за полсекунды, и муха, которая держит обиду минуту —
разные животные. Это параметр, а не деталь реализации.

### 3.4 Гомеостаз как медленная память

Потребности растут всегда. Ничто не может их «сделать», кроме реального
поведения: еда, вода, сон, спаривание. Это делает обучение долгосрочным —
выученное теряет смысл, когда условия меняются.

### 3.5 Сон как обязательная фаза

Обнаруженный при отладке баг, который стоило оставить: если сон не снижает
потребность во сне, состояние «сплю» становится поглощающим — муха засыпает
навсегда. Правильная физиология: **сон это то, что разряжает потребность во сне**.
Именно это и реализовано.

### 3.6 Что добавлять дальше, если нужен «человеческий» уровень

По возрастанию сложности:

1. **Предиктивная модель среды.** Сейчас реакция наступает сразу. Нужен
   внутренний прогноз «если я поверну туда, будет светло», и сравнение с
   реальностью. Ошибка прогноза — это и есть любопытство.
2. **Иерархия целей.** Прямо сейчас «лететь к источнику» — это вес в
   линейной политике. Нужна структура цель → подцель → действие, иначе
   поведение не будет иерархичным.
3. **Планирование через горизонт.** Не «куда повернуть сейчас», а «что будет
   через 10 секунд, если я выберу это».
4. **Социальное обучение.** Сейчас есть `TMateSignal`/`TRivalSignal`, но нет
   подражания. Взрослая муха учится у другой за секунды, без поощрения.
5. **Эмоциональная память.** Ассоциативная память привязана к действиям.
   Нужна привязка к состояниям: «после этого события я чувствовал X».
6. **Расстройства.** Депрессия, тревожность, мания — как устойчивые сдвиги
   параметров, а не как разовые вызовы.

## 5. Интеграция с проектом

### C

```c
#include "TFLY.h"

TFLY fly;
TNew(&fly);
TSeed(&fly, 7);

for (int i = 0; i < 600; i++) {
    TLight(&fly, 0.6f);
    TOdor(&fly, 0.5f, T_ODOR_FRUIT);
    TTick(&fly, 1.0f / 60.0f);
}
TPrintState(&fly);
```

### Rust

```rust
use flytest::tfly::{Fly, action, body, cue, emotion, odor};

let mut fly = Fly::new();
fly.seed(7);
fly.odor(0.6, odor::FRUIT);
fly.steps(20, 1.0 / 60.0);
fly.reward(0.6);
fly.associate(cue::ODOR_FRUIT, action::FORWARD, 1.0, fly.learning_gate());
println!("{}", fly.to_json());
```

### CLI

```powershell
cargo run --release -- tfly --scenario learn
cargo run --release -- tfly --scenario pain --trace 2
cargo run --release -- tfly --scenario social
```

## 6. Честное ограничение

`TFLY.h` — это **структурный прототип с реальной нейрохимией**, а не
измеренная модель нервной системы. Коннектом FlyWire даёт связность, но не
временные ряды мембранного потенциала и не концентрации гормонов в реальном
времени. Здесь моделируются правдоподобные *правила* (трёхфакторное обучение,
гомеостаз, рефлексы), а не измеренные величины.

Эмоции в коде — это **аффективные переменные**: числа, которые суммируются,
затухают и влияют на веса. Это не утверждение о том, что муха что-то
переживает, и тем более не перенос сознания.

Но для цифрового цирка это ровно то, что нужно: предсказуемо, отлаживаемо,
быстро, и ведёт себя как живое существо в наблюдаемых пределах.
